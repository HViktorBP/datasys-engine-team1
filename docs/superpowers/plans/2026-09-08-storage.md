# Storage Implementation Plan

**Goal:** Implement the approved [storage design](../../storage-design.md).
**Architecture:** A JSON catalog describes column chunks in one binary file per copy. StorageEngine coordinates bounded CSV ingestion, publication, restart, and filtered scans.
**Tech stack:** Java 25, Jackson catalog JSON, SLF4J, JUnit 6, Maven.

## Constraints

- Eight rows per partition by default; configurable positive maximum.
- Big-endian HTBD version 1 files; strict ASCII strings and exact Java predicate types.
- One successful copy per table; failed copies must leave the table retryable.
- Catalog-only canonical min/max; no chunk reads for pruned partitions.
- Preserve schema and input row order; sanitize dynamic log fields.

## Execution

- [x] Add failing unit tests for BinaryColumnCodec, CsvRowParser, PartitionStatistics, and PartitionPruner; implement their package-private interfaces and public value types.
- [x] Add failing integration tests for StorageEngine persistence, validation, all nine predicates, partition metadata, pruning without data access, malformed-copy rollback, and corrupt data. Implement CatalogStore and StorageEngine.
- [x] Configure Failsafe 3.5.6, add the golden CSV and isolated demo, document usage and ignore generated storage.
- [x] Run Maven verify and the no-argument demo; review the implementation against every design requirement.

## Verification cases

Codec tests round-trip all types and reject malformed framing; parser tests preserve trailing empty fields and report source/line. Integration expectations use literal golden row distances. Sorted rows in pairs must prune three partitions for distance > 200. Deleting a fully pruned binary file must still allow a successful empty scan. A bad final CSV row must publish neither data nor catalog registration and permit a retry. Restart must preserve schema, values, and partition sizes independently of the new constructor setting.

## Verification result

`mvn -B verify` passed: 7 unit tests and 14 integration tests.
`mvn -B compile exec:java` printed the three golden query results (4, 3, and 2 rows).
Independent review identified signed-zero numeric equality; the regression was reproduced and fixed in the shared comparator.
